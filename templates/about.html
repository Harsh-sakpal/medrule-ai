1. System Architecture (Three-Layer Design)

MedRule AI is engineered following an extensible Three-Tier Architecture that decouples the user interaction interface, the inference evaluation pipeline, and domain knowledge definitions.

Tier 1

Presentation Layer

Responsive Web Client developed using HTML5, modern CSS3 with glassmorphic tokens, and Vanilla JavaScript. Provides symptom checkbox grids, inference toggles, and live audit views.

Tier 2

Application / Inference Layer

Python Flask controller executing the EmergencyFilter, ForwardChainingEngine, and BackwardChainingEngine. Generates transparent step-by-step reasoning traces.

Tier 3

Knowledge Layer

Structured declarative production rules ($R_1 \dots R_6$), emergency indicators, and hypothesis definitions represented in Python dictionaries and JSON schema.

2. Mathematical Formalization of the Expert System

The expert system is formalized as a discrete tuple $\mathcal{ES} = \langle \mathcal{S}, \mathcal{F}, \mathcal{H}, \mathcal{R}, \mathcal{M} \rangle$:

  • Symptom Universe ($\mathcal{S}$): The finite set of all detectable observable symptoms:
    &S; = {sneezing, runny_nose, cough, fever, fatigue, body_ache, itchy_eyes, watery_nose, headache, facial_pressure, ...}
  • Working Memory Facts ($\mathcal{F}$): A subset of active observations asserted by the user: $\mathcal{F} \subseteq \mathcal{S}$.
  • Hypotheses Universe ($\mathcal{H}$): The set of candidate disease symptom profiles:
    &H; = {common_cold, allergy_rhinitis, influenza_like, sinusitis, gastroenteritis, migraine}
  • Production Rules ($\mathcal{R}$): A set of IF-THEN implication relations. A rule $R_i \in \mathcal{R}$ is defined as:
    $$R_i: \bigwedge_{s \in \text{Antecedents}(R_i)} s \implies \text{Consequent}(R_i)$$
  • Rule Satisfaction Predicate ($\mathcal{M}$): For Forward Chaining, a rule $R_i$ fires if and only if its required condition threshold is met:
    $$\text{Fires}(R_i, \mathcal{F}) \iff |\text{Antecedents}(R_i) \cap \mathcal{F}| \ge \tau_i$$

3. Inference Paradigm Comparison

Feature Forward Chaining (Data-Driven) Backward Chaining (Goal-Driven)
Starting Point Initial known facts (user symptoms) Target hypothesis / clinical goal
Direction of Search Bottom-Up (Antecedents $\to$ Consequents) Top-Down (Consequent $\to$ Antecedents)
Ideal Use Case Exploratory symptom analysis when user is unsure Verifying a suspected specific illness condition
Search Strategy Exhaustive breadth-oriented rule evaluation Depth-first verification of goal prerequisites
Time Complexity $O(|\mathcal{R}| \cdot \max |\text{Antecedents}|)$ $O(|\mathcal{R}_{goal}| \cdot |\text{Antecedents}|)$
